ASTRAEA — ML/CV, Digital Forensics & Multi-Channel Watermarking

Overview

This module implements the Machine Learning / Computer Vision and digital
forensics layer of Project ASTRAEA.

The primary responsibilities of this module are:

Embed a forensic payload into a visually identical document/image using
2D Discrete Wavelet Transform (DWT).

Recover the forensic payload from digitally transformed or physically
photographed media.

Support forensic W_ID embedding into decrypted text using invisible
zero-width Unicode characters.

Provide measurable extraction and robustness statistics for digital and
physical acquisition scenarios.

Ensure that the text and visual watermark channels carry the same
forensic identity.

Attribution, ledger lookup, cryptographic verification, key management,
and final FEC/identity interpretation remain outside the ML/CV layer unless
explicitly invoked by the integration layer.

The ML/CV layer must not generate an independent forensic identity.

The same forensic identifier (W_ID) generated by the upstream forensic
identity layer is used by both the visual and text watermark channels.

3. Single W_ID Principle

The upstream forensic identity layer generates the W_ID once.

Example:

wid_hex = ForensicIDEngine.derive_forensic_id(
    signature,
    committed_ledger_state
)

The result is:

256 bits
32 bytes
64 hexadecimal characters

That exact wid_hex must then be passed to both channels.

Visual channel

fec_payload = fec.encode_wid_for_dwt(
    wid_hex
)

watermarked_image = embed_watermark(
    image,
    bytes(fec_payload)
)

Text channel

watermarked_text = embed_wid_in_text(
    decrypted_plaintext,
    wid_hex
)

Never do this:

text_wid = generate_new_wid()
image_wid = generate_new_wid()

Always do this:

wid_hex = generate_wid_once()

text_wid = wid_hex
image_wid = wid_hex

5. DWT Watermarking Parameters

Current intended configuration:

Wavelet: Haar
Color space: YCrCb
Working channel: Y / luminance
Frequency bands: HL + LH
Embedding strength (alpha): 20.0
Coefficient offset: 128
Bit redundancy: use the repetition factor implemented by the current code

The HH band is not currently used because it is more vulnerable to camera,
JPEG, resampling, and physical acquisition distortion.

Important

Do not change DWT parameters merely to integrate the text channel.

The text watermark is an additional forensic channel. It is not a replacement
for the current visual watermark.

If the actual implementation uses a specific repetition factor, the README
must reflect the value in the code rather than an outdated design value.

6. Visual Payload

The intended backend input to the visual watermark is an FEC-protected byte
array of approximately 50 bytes.

The forensic W_ID itself is:

32 bytes
256 bits
64 hex characters

The FEC layer expands this into the protected payload used by the DWT channel.

Example:

wid_hex = ForensicIDEngine.derive_forensic_id(
    signature,
    committed_ledger_state
)

fec_payload = fec.encode_wid_for_dwt(
    wid_hex
)

fec_payload_bytes = bytes(fec_payload)

The DWT layer embeds fec_payload_bytes.

The FEC implementation is responsible for decoding the recovered payload back
into the original W_ID.

8. Accuracy and Recovery Metrics

Important: Do Not Use Only Exact 50/50 Equality

For a clean digital image, exact equality is appropriate:

50 / 50 bytes
100% direct byte equality

For a physical photograph, exact raw byte equality is only one metric.

For example:

26 / 50 bytes directly equal

is:

52% direct byte agreement

It should not automatically be described as:

"52% watermark accuracy"

because the payload is FEC protected and byte-level equality does not fully
describe bit-level corruption or final W_ID recovery.

9. Required Physical-Capture Metrics

Every physical capture should report at least:

9.1 Raw byte agreement

matching bytes / total bytes

Example:

26 / 50
52% direct byte agreement

9.2 Bit accuracy

Calculate:

correct bits / total bits

This is more granular than byte equality.

9.3 FEC result

Report separately:

FEC: SUCCESS

or:

FEC: FAILED

9.4 W_ID result

The final forensic-level result is:

Recovered W_ID == Original W_ID

Report:

W_ID: MATCH

or:

W_ID: NO MATCH

The most important distinction is:

Raw payload degradation
        ↓
FEC recovery
        ↓
W_ID recovery

11. Do Not Overclaim Physical Performance

The following distinction must be preserved:

Digital baseline:
50/50 exact payload recovery

versus:

Physical smartphone capture:
raw payload may contain errors

A physical result such as:

26/50 bytes = 52%

can be shown as a measured raw-recovery statistic.

It must not be converted into a claim of "52% forensic accuracy" unless the
evaluation methodology explicitly defines that metric.

The final forensic result should be evaluated at the W_ID/FEC level.

12. Text Watermark Channel

Purpose

The text channel embeds the same 256-bit forensic W_ID into decrypted text
using invisible zero-width Unicode characters.

The watermark must not alter the visible text content.

The recommended implementation file is:

ml/text_stego.py

Required API:

def embed_wid_in_text(
    text: str,
    wid_hex: str
) -> str:
    ...

and:

def extract_wid_from_text(
    text: str
) -> str:
    ...

Optional helper:

def visible_text(
    text: str
) -> str:
    ...

13. Text Watermark Encoding

Current mapping:

0 → U+200B ZERO WIDTH SPACE
1 → U+200C ZERO WIDTH NON-JOINER

The W_ID is:

256 bits
32 bytes
64 hexadecimal characters

The implementation should use explicit framing and integrity validation where
possible.

Recommended logical structure:

ASTRAEA START
VERSION
256-bit W_ID
CHECKSUM
ASTRAEA END

The framing itself may be represented through zero-width/control characters
as implemented by ml/text_stego.py.

The visible plaintext must remain unchanged.

14. Text Embedding Rules

embed_wid_in_text() MUST:

Accept plaintext as a Python str.

Accept a 64-character hexadecimal W_ID.

Validate that the W_ID is exactly 256 bits.

Convert the W_ID into 256 bits.

Encode the payload invisibly.

Preserve visible plaintext.

Return a Python str.

Avoid modifying the actual visible content.

Use the same W_ID as the visual watermark.

Be deterministic for the same text and W_ID.

Example:

watermarked_text = embed_wid_in_text(
    decrypted_plaintext,
    wid_hex
)

15. Text Extraction Rules

extract_wid_from_text() MUST:

Locate the ASTRAEA text watermark.

Validate the framing/version.

Decode the zero-width payload.

Recover exactly 256 W_ID bits.

Reconstruct the original 32-byte W_ID.

Validate the checksum/integrity field.

Return the W_ID as lowercase 64-character hexadecimal.

Raise an explicit exception when the watermark is missing or corrupt.

Do not silently return a garbage W_ID.

Example:

try:
    recovered_wid = extract_wid_from_text(text)
except ValueError:
    # watermark missing or invalid
    ...

16. Text Integration Point

The text watermark must be inserted after decryption.

Correct:

Encrypted document
       ↓
Decryption
       ↓
Decrypted plaintext
       ↓
Embed W_ID
       ↓
Watermarked plaintext
       ↓
UTF-8 document

The key integration code is:

decrypted_plaintext = decrypt(...)

watermarked_text = embed_wid_in_text(
    decrypted_plaintext,
    wid_hex
)

Do not create a separate forensic identity during this step.

17. UTF-8 Requirements

Watermarked text MUST be saved and loaded as UTF-8.

Correct:

path.write_text(
    watermarked_text,
    encoding="utf-8"
)

and:

text = path.read_text(
    encoding="utf-8"
)

Do not use an encoding that removes, replaces, or corrupts the zero-width
characters.

18. Visible-Text Preservation

The watermark must not visibly change the document.

A helper can remove invisible formatting/control characters:

visible = visible_text(watermarked_text)

assert visible == plaintext

This test is mandatory.

The following must remain unchanged:

words

punctuation

spaces

line breaks

visible characters

document meaning/content

Only invisible watermark characters may be added.

34. Final Principle

ASTRAEA should not be redesigned for the final demonstration.

The existing DWT/FEC implementation is the visual watermarking channel.

The text watermark is an additional channel carrying the same forensic
identity.

The target system is therefore:

                    ONE W_ID
                       |
          +------------+------------+
          |                         |
          v                         v
    TEXT WATERMARK            VISUAL WATERMARK
    Zero-width Unicode        FEC + DWT
          |                         |
          v                         v
    Text document              Image/document
          |                         |
          +------------+------------+
                       |
                       v
                 Same forensic ID

The objective is not perfect raw-payload survival under every physical
condition.

The objective is measurable and reproducible forensic identity recovery,
with transparent reporting of:

Raw payload degradation
        ↓
Bit/byte recovery
        ↓
FEC recovery
        ↓
W_ID recovery
        ↓
Cross-channel identity verification

The final demo should demonstrate that one forensic identity can be carried
through both text and visual channels while preserving the existing ASTRAEA
DWT/FEC architecture.
